# RefurbishedKart — Deployment Checklist

## Invoices (private GST PDFs)

- [ ] **`private/` directory is writable** by the Node process. Invoices are written
      to `private/invoices/*.pdf` at runtime (outside `public/`, so they are never
      served as static files). On the VPS, ensure the app user owns the project dir.
- [ ] **`private/` is git-ignored** (already in `.gitignore`) — never commit customer PDFs.
- [ ] **Back up / persist `private/invoices/`** if you wipe the deploy dir on release.
      Missing files are lazily regenerated by `GET /api/invoices/[orderId]`, but only
      while the source order still exists in MongoDB.
- [ ] Access is gated by `GET /api/invoices/[orderId]` (JWT required; customers get
      only their own orders, admins get any). There is **no** public/static path to a PDF.

> Debug logging note: all logging goes through `lib/logger.js` (`log` / `logError`),
> which is silent when `NODE_ENV === "production"`. Raw `console.*` is blocked by the
> `no-console` ESLint rule (`.eslintrc.json`); `lib/logger.js` is the only exception.
> No manual log removal is required before go-live.
- [ ] Run `npm install` so `eslint` + `eslint-config-next` are present, then confirm
      `npm run lint` passes — this is what makes the `no-console` rule actually enforce
      (ESLint was not previously installed in this project).

## pdfkit fonts (PDF generation)

- [ ] **REQUIRED in every environment (dev + prod):** `next.config.js` must keep
      `experimental.serverComponentsExternalPackages: ["pdfkit"]`. pdfkit reads its
      `.afm` font metrics from `node_modules/pdfkit/js/data/*.afm` at runtime; if
      webpack bundles pdfkit, those files aren't traced and `new PDFDocument()` throws
      ENOENT, so invoices silently fail to generate. This config makes Next require
      pdfkit from `node_modules` instead of bundling it. **Do not remove this line.**
- [ ] Confirm `node_modules/pdfkit/js/data/*.afm` ships in the deployed build
      (it lives in `node_modules`, so a normal `npm ci` on the VPS includes it).
- [ ] Invoice generation is **best-effort** in `app/api/payment/verify` — wrapped in
      try/catch so a PDF failure never blocks payment confirmation. A missing invoice
      is regenerated on first download. Because failures are swallowed, watch the
      server logs (or wire an alert) so a broken generator doesn't go unnoticed.

## Environment / secrets

- [ ] `.env*` is git-ignored. Set on the server: `MONGODB_URI`, `JWT_SECRET`,
      `RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `NEXT_PUBLIC_RAZORPAY_KEY_ID`,
      `ADMIN_EMAIL`, Google OAuth + SMTP vars.
- [ ] **Remove the `requireAdmin` DEV bypass** (`NODE_ENV==="development"` mock
      superadmin in `lib/server/adminAuth.js`) before/at production — `NODE_ENV=production`
      disables it, but confirm.
